> **22 NOVEMBER 2026 — UNIFIED AUTO: ONE BUTTON, ONE STRENGTH SLIDER, SPECIES-AWARE COLOUR (stage two).** The Auto tab's *Suggest a look*, Edit's *Check colour* panel, *Check photo* and the three #839 suggestions are replaced by `AutoControl` (a single **Auto** button with a pulsing icon beside a **Strength** slider). One press measures the unedited colour-managed preview on this device, builds ONE recipe (`naturalAuto` sliders + subject mask + optional species colour), runs it through the existing `stageNaturalRecipe` gate and applies it as ONE undoable step (`src/core/unifiedAuto.ts`, `planAuto`). The slider scales the whole recipe (`recipeAtStrength`, previewed live, committed once); **Undo Auto** restores exactly the starting look; the applied edit is an ordinary recipe, so reopen keeps it (the slider itself needs a new press after reopening: the plan is not stored). Honesty rules, unit-tested: **"Looks good" only when the measured values are inside their stated ranges** (subject lightness 30 to 85%, brightest detail under 97.5%, no Colour Check warnings; low-key scenes keep their mood); a **dark photo gets a real exposure lift** (synthetic frame at level 0.07: +1.5 units) **or** "Cannot improve this safely: …" with nothing applied (level 0.03: declined by the noisy-shadow gate). Reduced motion stops the pulse (`motion-safe:`); the outcome is a word plus a distinct icon, never colour alone. **Species stage:** `autoSpecies.ts` names the subject on-device (BioCLIP-style embedding match behind the existing category gate) and `speciesPalette.ts` compares the subject's measured hue (preview pixels on a high-confidence mask, so display calibration is irrelevant) with a signature colour (robin breast, bullfinch, goldfinch, yellowhammer, great tit). It corrects warmth (max ±0.4, inside the same gate and slider) **only** when the name is ≥85% and leads the runner-up by ≥0.6; it **abstains** on low confidence, no mask, an unknown species, a far-off hue, or a warm-light cast (golden hour), and always says "evidence, not authority". **Model install is automatic:** the first Auto press starts the species model download as a Task Manager entry with progress and Stop (no Edit-menu choice); Auto never waits for it. #703's on-device description (when the desktop pack is installed) shows as one plain line after Auto and never sets a number. Removed as orphaned: `ColourCheckPanel`, `LocalPhotoCheck`, `photoTreatments`, `localVisionLabels`, their specs; `AiReviewPanel` stays (used by Appearance). **Checks:** `npm run lint` PASS; `npm test` 1958 pass / 0 fail / 1 skipped (9 new in `unifiedAuto.test.ts`); `npm run build` PASS (run by Playwright's web server); Playwright desktop on its own port: `auto-unified` (3), `auto-summary`, `insight-preview-apply` PASS; `photo-workflow`, `auto-cull-500-to-20`, `auto-look-previews` FAIL identically on clean main (known stale baseline, failing before any Auto step). **NOT RUN:** phone project, the full Playwright suite, `cargo test` (no Rust change), a real photo of a robin through the built app with the real BioCLIP model (the species palette is unit-tested on synthetic pixels only), the real vision pack, Windows, translations (new labels are British English only, in `src/i18n/autoLabels.ts`). **Rebrand overlap:** edits `PhotoEditor.tsx` (Auto tab body, Edit tab tail, imports); new text avoids product names. Status label: **unified flow working in the editor on synthetic and demo photos; species correction is unit-tested but unproven on real bird photographs.**

## 3. The order of work

Work runs P0, then P1, then P2, then P3, then P4. Inside each, take the items in order; inside P0, take the first item that isn't blocked.

**Our own engine, the same on every device.** Models ship as ONNX and run through onnxruntime (WASM now, WebGPU next) on Windows, macOS, web, iOS and Android alike. The RAW decoder (rawler, Rust) runs natively on desktop and should be compiled to WebAssembly for web and mobile, not replaced per platform. Platform code stays in the adapters (`src-tauri/`, `src/providers/`). Start from proven open work (BioCLIP 2, YOLOX, open lens data, published denoise networks) and learn from other people's published mistakes before making our own. Keep a licence register: anything licensed non-commercial only is marked, so it can't reach a commercial release unnoticed.

**Offline first, online only when Kestrel genuinely doesn't know.** Local models always answer first. Kestrel asks online only when (a) the local answer is below its confidence threshold or abstains, (b) the user has consented, and (c) the device is online. Otherwise the question waits in a queue or stays "unknown". Online answers never overwrite a user decision, and feedback is opt-in. Hosting and learning in the cloud (Vertex or similar) get a budget only when we decide to deploy; until then learning is local (P2).

## 20 November 2026 — photo stacking and merging (new future capability)

**Scope:** add an authentic, non-generative stacking/merging workflow after the core prototype's image, interface and performance work. It must not create or replace depicted objects.

- **Burst alignment:** feature/subject-aware alignment, global transform then fine local refinement. Detect moving birds, foliage and subject boundaries; do not ghost the subject. Refuse ambiguous registration, preserve an original fallback.
- **Focus stacking:** alignment followed by sharp-region selection with feathered transitions; review a preview and confidence/artefact warnings before saving.
- **Exposure blending / HDR:** fuse real exposures using linear high-bit-depth pixels with natural highlight roll-off, colour management and movement masks; no hallucinated detail.
- **Noise / astro stacking:** register repeated shots and combine real measurements for detail/noise improvement, with motion-aware rejection and a visible choice of which frames contribute.
- **Panorama merge:** homography/lens-aware registration, seam finding and cropping; keep source provenance and offer a TIFF master.
- **Workflow:** group bursts into a representative tile for browsing (reversible UI-only choice); select frames; compare contributors; render a reversible composite with non-destructive sidecars, exact source IDs, original metadata and destination; export 16-bit TIFF when genuinely supported.
- **Quality gates:** match exact pixel dimensions, luminance/colour precision, edge seams, feather/leg detail, halo/double-image rate, memory caps, CPU/GPU fallback, cancellation/restart and offline execution. Test Nikon RAW/JPEG/HEIC/TIFF mixtures and near-duplicate/low-texture scenes. When measurements are absent, abstain rather than display a fabricated quality score.
- **Resource control:** bounded background worker queue; chosen photograph remains responsive. Stack state persists across Library/Review/Edit without generating duplicates.

**Design decision:** stacking is optional, not mandatory for the one-photo import-to-export path. All merged pixels must derive from user-owned source photographs; generative additions/removals remain out of scope.

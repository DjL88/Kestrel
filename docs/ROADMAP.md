### 20 November 2026 — partial desktop background export retry (same session only)

**Code authored, tests NOT RUN.** If a desktop-folder Export Flight fails after one or more files, Task Manager now offers an explicit **Retry** for the remaining files in the **same running application session**. The submitted per-photo formats, filenames, crops, metadata, overlays and watermark choices stay frozen; successful earlier files are skipped, and the new Task Manager entry continues progress from the known number completed. Each desktop write is exclusive `createNew` and cannot silently replace a file. Retries are opt-in, capped at three, and only retained for five failed jobs to bound source/connection memory. Cancelled/completed tasks and remote cloud/NAS exports are **not** retryable: remote PUTs may have committed despite an error and are not yet guaranteed no-overwrite. A successful retry dismisses only the original resolved failure, not other task errors. The new Task Manager action is localised in all full language packs.

**Not yet implemented:** durable restart recovery, independent SHA-256 verification of source and output identities, atomic fsync/rename receipts, and resuming a remote destination after permissions are reacquired. The existing `exportQueueJournal`/`journalledExportDispatch` is a library abstraction, not yet a verified active cross-process workflow. This work must **not** be represented as crash-safe export. **NOT RUN:** TypeScript, regression tests, build, installed filesystem/NAS/device checks.

### 20 November 2026 — private local image-watermark asset vault (code under review)

Image watermark originals are stored as validated PNG/JPEG/WebP blobs (up to 3 MB) in a **private device-local IndexedDB asset store**, addressed and checked by SHA-256. Export settings and saved presets retain only the asset fingerprint and presentation controls, not full image bytes. On Export opening or preset recall, Kestrel resolves the asset into a transient, in-memory renderer data URL for the existing live proof and batch export; no cloud API, upload, or project backup is involved. New selections are persisted before activating. Historic inline marks are migrated locally before overwriting the old preference, and legacy inline presets migrate when next saved. Invalid, absent, altered or unavailable saved artwork **blocks export** instead of silently omitting a requested mark. The user is told that device-specific artwork must be chosen again on another device. Encrypted operating-system key storage for third-party API credentials is a separate P0 gap and is **not** supplied by this watermark vault.

**Tests authored, NOT RUN:** content-digest deduplication and read-back integrity, invalid/missing/script sources, legacy data conversion, preset privacy, and stored custom upscale. ### 20 November 2026 — explicit camera-original export (code under review)

Export now has a distinct **Save original file(s)** action for real linked photographs. This path reads the **original stored bytes** via `BrowserPreviewProvider.ensureOriginal`; it never opens the edit canvas, demosaics, resamples, masks, adds watermarks, rewrites EXIF/XMP or substitutes a cached embedded/review preview. It wraps the original `Blob` with a collision-safe name matching the camera extension and, where known, the original modification time; the source itself remains untouched. Missing/demo/truncated/changed-size sources fail rather than exporting something claimed to be the original. The person is explicitly warned that **original EXIF, GPS/location, serial data and all other private camera metadata remain present** in the copied file, and edited recipes do not transfer. It is a copy, not an edited export, so it does not consume a Free edited-export allowance.

On desktop one picked destination leads to Task Manager processing originals sequentially into an `Original/` subfolder, using the existing exclusive-create, no-overwrite and incomplete-write cancellation behaviour. On web/mobile a single real original may be saved directly and small batches may be downloaded as a ZIP. Browser batches are capped at 128 MB total for bounded memory; large RAW batches must use a desktop folder destination until a proven browser streaming-directory route is available. If the desktop queue or the app process terminates, the queue still lacks restart-resumable atomic commits; this feature **does not claim durable cross-restart recovery**.

**Unit and UI checks authored but NOT RUN:** exact-byte original preservation, duplicate/case-insensitive camera filenames, unsafe name rejection, missing/truncated demo sources, early cancellation. Full TypeScript/lint/test/build/Playwright, installed Mac/Windows and browser/mobile, real Z8/Z5II 500-photo batch, source hash evidence, local NAS disconnect and 128 MB memory behaviour remain pending. Other implementation gaps persist, so the full roadmap is not yet legitimately testing-only.

## 3. The order of work

Work runs P0, then P1, then P2, then P3, then P4. Inside each, take the items in order; inside P0, take the first item that isn't blocked.

**Image first (owner decision, 18 Nov 2026).** Kestrel wins on picture quality and calm speed, not on breadth. Until P1.1 lands (one 16-bit float pipeline that the screen and export share), these areas are **frozen**: no new features in `services/control-plane`, licensing, S3/WebDAV connectors, sync, MCP or new planning documents. Fix bugs and security issues there; build nothing new. The control plane stays merged and tested, but nothing deploys it.

**Our own engine, the same on every device.** Models ship as ONNX and run through onnxruntime (WASM now, WebGPU next) on Windows, macOS, web, iOS and Android alike. The RAW decoder (rawler, Rust) runs natively on desktop and should be compiled to WebAssembly for web and mobile, not replaced per platform. Platform code stays in the adapters (`src-tauri/`, `src/providers/`). Start from proven open work (BioCLIP 2, YOLOX, open lens data, published denoise networks) and learn from other people's published mistakes before making our own. Keep a licence register: anything licensed non-commercial only is marked, so it can't reach a commercial release unnoticed.

**Offline first, online only when Kestrel genuinely doesn't know.** Local models always answer first. Kestrel asks online only when (a) the local answer is below its confidence threshold or abstains, (b) the user has consented, and (c) the device is online. Otherwise the question waits in a queue or stays "unknown". Online answers never overwrite a user decision, and feedback is opt-in. Hosting and learning in the cloud (Vertex or similar) get a budget only when we decide to deploy; until then learning is local (P2).

## 20 November 2026 — photo stacking and merging (new future capability)

**Scope:** add an authentic, non-generative stacking/merging workflow after the core prototype's image, interface and performance work. It must not create or replace depicted objects.

- **Burst alignment:** feature/subject-aware alignment, global transform then fine local refinement. Detect moving birds, foliage and subject boundaries; do not ghost the subject. Refuse ambiguous registration, preserve an original fallback.
- **Focus stacking:** alignment followed by sharp-region selection with feathered transitions; review a preview and confidence/artefact warnings before saving.
- **Exposure blending / HDR:** fuse real exposures using linear high-bit-depth pixels with natural highlight roll-off, colour management and movement masks; no hallucinated detail.
- **Noise / astro stacking:** register repeated shots and combine real measurements for detail/noise improvement, with motion-aware rejection and a visible choice of which frames contribute.
- **Panorama merge:** homography/lens-aware registration, seam finding and cropping; keep source provenance and offer a TIFF master.
- **Workflow:** group bursts into a representative tile for browsing (reversible UI-only choice); select frames; compare contributors; render a reversible composite with non-destructive sidecars, exact source IDs, original metadata and destination; export 16-bit TIFF when genuinely supported.
- **Quality gates:** match exact pixel dimensions, luminance/colour precision, edge seams, feather/leg detail, halo/double-image rate, memory caps, CPU/GPU fallback, cancellation/restart and offline execution. Test Nikon RAW/JPEG/HEIC/TIFF mixtures and near-duplicate/low-texture scenes. When measurements are absent, abstain rather than display a fabricated quality score.
- **Resource control:** bounded background worker queue; chosen photograph remains responsive. Stack state persists across Library/Review/Edit without generating duplicates.

**Design decision:** stacking is optional, not mandatory for the one-photo import-to-export path. All merged pixels must derive from user-owned source photographs; generative additions/removals remain out of scope.
